# RISKS (remaining mathematical and implementation risks)

| # | Risk | Severity | Mitigation / status |
|---|---|---|---|
| R-01 | **Quadrature far tails.** For targets far in the predictive tail, the dominant a may lie outside the posterior window, so log densities there are underestimated. | Low for log score at realistic targets; unknown for extreme-tail metrics | Convergence verified at predictive quantiles 1e-3..1-1e-3 (A3) and at actual targets in every experiment cell. Beyond that: **UNVERIFIED**. |
| R-02 | **The resolution-cell heuristic is a heuristic.** The adaptive panel placement (MATH 5.2) is justified by convergence tests, not by an error bound. Its first version passed my own tests and was still wrong in regimes I had not tested (the independent audit found them). | Medium in untested regimes (h > 50, abs(a) > 1.1, x_0/sigma > 400) | A3 now covers the audit's regimes as well. Cap hits are flagged. Run `check_quadrature_convergence` before extending the regimes, and extend A3 with the new regime. |
| R-03 | **The independence assumption for x_0 is load-bearing.** Any future simulator that starts from the stationary distribution or burns in, or any context cut mid-trajectory, silently invalidates the matched reference. | High if violated | Enforced at the single context-cutting point. Calibration tests (E) would detect it. MATH 1.2 documents it. |
| R-04 | **Statistical tests have finite power.** A subtle bug (e.g. a 5% variance error at large n) could pass E and F. | Medium | The mutation tests show realistic bugs are caught. Power against small biases is not quantified. Power grows with sqrt(N) via `n_items`. |
| R-05 | **Fixed seeds.** Statistical checks were run at one seed each. A different seed could fail by chance with probability <= 1e-3 per check. | Low | Documented alpha. A failure on reseeding should be investigated, not ignored. |
| R-06 | **Oracle limitations.** scipy truncnorm loses accuracy in deep tails (D-07). The NIG 2-D grid has range-truncation error of ~1e-8 at n = 2. | Low | Oracle errors are measured and enter tolerances explicitly. Adequacy bound 1e-6. |
| R-07 | **The OLS Student-t h > 1 variant and persistence with n < h are heuristics.** | Low (baselines only) | Labelled heuristic. Their calibration is reported, not assumed. |
| R-08 | **Kernel baseline with short contexts.** Few validation points make the bandwidth and variance noisy, and blocked CV often has no valid fold at n = 10, h = 3 (it then uses the plug-in rule). | Medium for conclusions about the "parroting" baseline at small n | Fallback rates are reported per cell. The kernel scheme comparison (K) measures the effect. |
| R-09 | **Frontier selection uses population information at the meta level** (D-06), and `frontier_all` includes a sigma-informed member (D-05). | Medium for interpreting G | Both frontiers are reported. A truly context-only frontier would need selection without population data, which is not defined in Stage 0. |
| R-10 | **G is ill-conditioned wherever the matched reference barely beats the frontier.** | High in large-n cells | Flagged per cell (MATH 9). Do not report G where it is flagged. |
| R-11 | **No git provenance.** Runs cannot be tied to a commit until the workspace is a repository. | Medium | Recorded explicitly. `git init` and commit before Stage 1 runs. |
| R-12 | **Platform determinism.** Bitwise reproducibility is verified on one machine (Windows, numpy 2.2.2). Other BLAS/OS builds may differ in the last bits. | Low | Checksums are recorded. Cross-platform comparison should use tolerances, not bitwise equality. |
| R-13 | **P-STABLE posterior near the boundary with huge S_xx** collapses to sub-ulp windows. The implementation then returns a point mass. | Low (only reachable with explosive data under a stable prior) | Covered by numerics tests (H) for abs(a) = 0.999 and 1.1 data. |
| R-15 | **Grid cells share random numbers** (D-24). | Low for per-cell claims; medium for pooled claims | Do not treat the 60 cells as independent replicates when aggregating. |
| R-16 | **The kernel predictive variance is the minimum validation MSE over 8 bandwidths**, which biases it low. | Low (baseline only) | Documented. Its calibration is reported per cell. |
| R-14 | **Only scalar AR(1) with Gaussian noise.** Nothing here validates behaviour for observation noise, VAR, or chaotic systems. | — | Out of scope (Section 0.8). |
| R-17 | **The authorization gate is not a security boundary against someone who can edit and run code outside the frozen tree, or who holds the key.** A Python caller can also build the gate object by hand. | Medium | Documented in docs/STAGE06_AUTHORIZATION_GATE.md; the real control is that the key and the expected manifest hash are held by the user. A second run under a new run id in a different directory is not prevented. |
| R-18 | **Colab qualification of the frozen runner has never been run.** Local rehearsals (Windows) passed; Colab differs in Python patch version, platform and BLAS, so the runner will refuse until `qualify` passes there. | Medium | The pilot notebook (colab/pilot/..._v2.ipynb) runs it with the frozen pilot config; results pending from the user. |
| R-19 | **Pilot-seed isolation depends on tooling discipline.** Pilot outputs carry no explicit run-kind field; they are rejected by config-hash binding. Pilot effect estimates exist (PILOT_ONLY_do_not_open_effects.json and checkpoints). | Low | Pilot seeds only; never opened; seed search over all pilot outputs found no confirmatory seed. |
| R-20 | **Planning assumptions behind the sample-size claim** (how much noise inflates the per-system spread, correlation across noise levels) are not estimable from Stage 0.5. If the inflation is large, STOP becomes hard to reach (REVISE results). | Medium | Dry run covers inflation 1 and 2; stated in the pre-registration. |
| R-21 | **Tests that pass vacuously, and tests that can block on interactive input.** The notebook-scan test passed vacuously until a notebook existed (F18); a key-prompt fallback hung a run for hours (F17). | Low | Both fixed; scans are re-run on the final artifacts; tests run with a non-interactive stdin. |
| R-22 | **Frozen files can be rewritten by tooling run at the wrong time** (the freeze tool's verify step did it twice: F1, F8). | Low | The v2 tool refuses record, verify and freeze once the manifest exists; hash comparison after every task group. |
