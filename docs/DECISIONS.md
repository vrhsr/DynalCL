# DECISIONS

Each entry: the decision, its rationale, and its status (ASSUMED design choice, or forced by a TESTED
finding). Decisions marked *found by a test* changed code after a validation check failed or after
writing a check exposed a flaw.

| ID | Decision | Rationale | Status |
|---|---|---|---|
| D-01 | All code lives under the `dynaicl/` package (`dynaicl/systems`, `references`, `baselines`, `metrics`, `evaluation`, `validation`, `experiments`, `config`), with YAML in top-level `config/`. | Top-level packages named `metrics` or `config` can collide with installed packages. The structure otherwise follows Section 6. | ASSUMED |
| D-02 | No new dependencies. The YAML schema is strict typed dataclasses (unknown or missing keys, wrong types and bad ranges all raise). | The default stack suffices. `jsonschema` is installed but not needed. | ASSUMED |
| D-03 | x_0 ~ N(0, 1), drawn independently of the system. Contexts always start at x_0. | Needed for the conditional-likelihood posterior to be exact Bayes (MATH 1.1-1.2). | DERIVED requirement; value ASSUMED |
| D-04 | Experiment prior: P-STABLE truncated normal, mu0 = 0.4, tau0 = 0.3, rho = 0.95. | Moderately informative and asymmetric, with about 3% of the untruncated mass beyond 0.95. Chosen before any result was seen and not tuned. | ASSUMED |
| D-05 | Flat-prior Bayes receives the condition's sigma as a config hyperparameter and is flagged `uses_true_noise_scale`. Two frontiers are reported: `frontier_all` and `frontier_strict` (excludes sigma-informed members). | The spec requires "flat-prior Bayes (known sigma)", but sigma is population information. Reporting both keeps the frontier honest. | ASSUMED |
| D-06 | The frontier member is chosen on a selection split drawn from the same condition (independent `selection_*` streams), separately per (condition, sigma, K, n, h), on mean log score. | "Best" is only defined relative to a distribution. The single discrete choice uses population information at the meta level, while each member's predictions stay context-only. | ASSUMED |
| D-07 | The `scipy.stats.truncnorm` moment oracle uses a 1e-9 relative floor. The grid oracle keeps 1e-11. | *Found by a test (A2):* scipy's truncnorm variance was off by 6.1e-11 in a deep-tail case, while quadrature matched a 2e6-point Simpson rule to ~1e-16. The reference was right and the oracle was imprecise. | TESTED |
| D-08 | Quadrature panels are placed at equal quantiles of a resolution density (uniform part + 2 panels per integrand "resolution cell", MATH 5.2), capped at 8192 panels, with cap hits flagged. | *Found by a test (A3):* a fixed 128 nodes failed by 2 nats (P-GAUSS a ≈ 0.99, x_n = 10, h = 50). *Then found by the independent audit:* uniform panels were still under-resolved for wide posteriors with large x_0/sigma (2e-5 nats). Worst A3 error is now 1.7e-13 nats, with the audit regimes added to A3. | TESTED |
| D-09 | Kernel analog: direct h-step NW regression. Each validation row's bandwidth scale is computed only from data that row may read. Variance = mean squared validation residual. Exact MSE ties go to the larger bandwidth. Fallbacks: Silverman plug-in bandwidth when there are too few validation points; persistence when there are fewer than 3 pairs. | *Found while writing J4:* the first draft scaled bandwidths by sd(whole context), which reads post-origin data during rolling-origin validation. | TESTED (J4 with positive control) |
| D-10 | Short-context fallbacks: flat prior uses a proper N(0, 1) prior when S_xx = 0; OLS falls back to persistence when n < 3 or S_xx = 0; persistence with n = 0 uses config variance x h. Every fallback is flagged in `info`, and the experiment reports fallback rates. | The estimators are undefined there. Config-fixed choices keep the predictors context-only. | ASSUMED |
| D-11 | SBC for quadrature posteriors draws the rank as Binomial(L, F(a*)). | Equal in distribution to L inverse-CDF draws (MATH 8.4), and needs no per-draw root finding. | DERIVED |
| D-12 | Coverage is computed from the PIT. | Equivalent for continuous F (MATH 8.3) and avoids root-finding. | DERIVED, TESTED |
| D-13 | Streams are keyed by SHA-256 of the name, with per-item children keyed by (name, condition code, index). The same items are used across sigma, n, h (common random numbers). Libraries are nested across K. | Adding streams or items never shifts others, and grid comparisons are paired. | TESTED (Section I) |
| D-14 | T1 uses a one-sided z from a Bonferroni split of family alpha = 1e-3 over every comparison in the run. T2 uses Bonferroni over cells x (KS + coverage levels). | Stated false-alarm probability under correct code. | ASSUMED |
| D-15 | A predictive that float64 cannot represent raises `FloatingPointError`. Quadrature nodes holding <= 1e-15 posterior mass with overflowing moments are dropped. | "No NaN or inf anywhere": the only honest options are a correct finite answer or an explicit error. *Found by a test (H)*, whose first version used an unrepresentable case. | TESTED |
| D-16 | Timing data goes only into `provenance.json`, never into `results/`. | *Found by a test (I):* per-cell seconds in `units.csv` broke bitwise reproducibility. | TESTED |
| D-17 | NIG beta_n uses RSS(mu_n) + lambda0 (mu_n - mu0)^2. | Same value as the spec's formula, without cancellation (MATH 3.1). | DERIVED |
| D-18 | Library atoms carry their own sigma_k (equal to the condition's sigma under P-STABLE). | The spec's library likelihood uses sigma_k. | ASSUMED |
| D-19 | Mutations monkeypatch a single module attribute: the prior-moment helper, `ar1.transition_pairs`, `harness.make_context`, or `matched.matched_reference_for`. A fifth variant also disables the guard function `matched.check_system_distribution`. | Each bug is injected exactly once, where all callers see it. The bypass variant measures whether the statistical checks alone would catch an unmatched reference. | ASSUMED |
| D-20 | P-NIG h > 1 is not implemented. | Not required by the spec. Listed as future work. | — |
| D-21 | CRPS is off in the experiment (`metrics.compute_crps: false`). Log score is primary. | Numerical CRPS for 128-node mixtures across ~10^6 items is CPU-expensive. CRPS code is validated in `tests/test_metrics.py`. | ASSUMED |
| D-23 | The grid oracle takes prior densities from scipy.stats, not from the reference's `coefficient_logpdf`. | *Independent audit:* the shared function made the grid non-independent for the prior density. | TESTED (A1, A2, C2) |
| D-24 | Common random numbers: every E-CONT condition uses stream code 0, so different priors and both sigma cells share x_0/noise draws (and the same uniform for a). Library atoms are identical across sigma. | Deliberate (paired comparisons across the grid). Consequence (raised by the audit): **cells are not independent replicates**. Per-cell inference and Bonferroni (valid under dependence) are unaffected, but any claim pooled across cells must account for the correlation. | ASSUMED |
| D-22 | No `git init` and no commits were made. Provenance records git as unavailable, with the reason. | The workspace is not a repository, and initialising or committing was not requested. | — |
| D-25 | Stage 0.5 adds a generic-stability Bayes member (uniform prior on (-0.999, 0.999), known sigma) to the context-only family. The primary comparator `frontier_ctx` is the best of 8 members. | It uses no population data, only "systems are stable", so it is context-only under the Stage 0 definition. Leaving it out would credit generic structural knowledge to "population knowledge" and overstate the primary effect. The Stage 0 frontier is reported for continuity. | ASSUMED (pre-registered in PREREG_stage05 §2) |
| D-26 | Stage 0.5 fixes sigma = 1 and varies r = sd(x_0)/sigma in {0.25, 1, 4}. | Paired log-score differences are invariant to a common rescaling of (x, sigma) (MATH 11), so r is the only scale that matters. | DERIVED, TESTED (`test_scale_equivariance_of_paired_differences`) |
| D-27 | Stage 0.5 uses independent seed roots per role (library 52001, selection 52002, evaluation 52101/52102, bootstrap 52999; pilot 51001-51004). The frontier is selected once on the selection split and frozen for both evaluation replicates. A class counts only if both replicates agree. | Stage 0 results guided the design, so the confirmatory data must be fresh, and replication protects against selection bias and multiplicity. | ASSUMED (pre-registered) |
| D-28 | Long Stage 0.5 runs checkpoint each finished unit (pickle under `<checkpoint-dir>/<config-hash>/`) and resume. The Colab notebook writes checkpoints and results to Google Drive. | A ~2 h Colab job must survive disconnects (a previous Colab archive was lost to a recycled runtime). Units are pure functions of (config, unit), so a resumed run is bitwise identical. | TESTED (`test_checkpoint_resume_gives_identical_results`) |
| D-29 | Stage 0.5 outcome: REVISE (pre-registered rule, applied mechanically). The run was imported from the user's Colab archive (`colab/*.tar.gz`), safely extracted, hash-verified and copied to `runs/`. | P1 held; P2 failed at h = 5; P3 failed at r = 4. Thresholds, N and rules were not changed after the results. | TESTED |
| D-30 | Stage 0.6 models noisy observation y_t = x_t + sigma_v nu_t of a latent AR(1) with a latent x_0 ~ N(0, (r sigma_w)^2) independent of a. The population reference and the comparator are Bayes posterior predictives with a Kalman likelihood on a shared quadrature node set; they differ only in the prior over a. | The pair isolates the value of population knowledge (information parity V11). Zero-noise nests Stage 0.5 (Tier-1 reproduces 243,216 stored items to 9.3e-15). | TESTED (V1-V19) |
| D-31 | The Stage 0.6 comparator is LOCKED to noise-aware stability-only Bayes; noise-naive baselines are secondary and labelled noise-misspecified. Noise levels q = 0.755 / 2.56 / 6.5 were kept (asymptotic Fisher-information retention 1/2, 1/4, 1/8); finite-n retention over n in 10..40 is documented and the levels are never called equivalent to shorter contexts. | The user's Phase C decisions; selection audit found no alternative beating stability (0/240, 0/576). | DERIVED + TESTED |
| D-32 | Inference: system-level L-average (n = 10..40), per-system paired gains, cluster bootstrap over whole systems with identical indices across 36 contrasts (18 gains + 18 noise increments), studentized max-|t| simultaneous band (alpha 0.05 per replicate), flags G+ / I+ / G- / NEG, SUPPORTED, Q(h, r), decision order BLOCKED, GO, STOP, REVISE. | Systems are the independent units; contexts within a system are not. A false GO needs a false SUPPORTED in both replicates (<= alpha^2). | TESTED (V20-V23, dry run) |
| D-33 | Stage 0.6 integrity is SHA-256 manifests plus read-only snapshot archives, not git. The v1 freeze (manifest 461dfec8...) is preserved untouched; changes go into a new version label (v2) created alongside. | The user forbids `git init` without asking again; a manifest beside its files protects only against accidents, so its hash is stored outside the workspace by the user. | VERIFIED |
| D-34 | Confirmatory execution needs an authorization artifact: HMAC-SHA256 under a key only the user holds, binding the frozen state, exact seed set, run id and validity; verified at start, on each resume and at completion; one run id per checkpoint directory. Test-only artifacts and keys can never authorize. | A hash-only artifact is forgeable by anyone who can write files, including the agent. HMAC needs only the standard library; an asymmetric signature would need a vetted dependency. Limits are documented (docs/STAGE06_AUTHORIZATION_GATE.md). | TESTED (V25, 12 mutants) |
| D-35 | Runner outcomes are REFUSED (policy, exit 3) and CORRUPT (integrity, exit 4), raised at the specific failing check, never via a catch-all. Unit checkpoint metadata carries its own checksum (schema v2). | Phase D found uncaught tracebacks for a truncated unit JSON and a missing qualification path; the fuzz requirement needs a checksum-verified load, and v1 metadata had no checksum. | TESTED (V26, V27) |
| D-36 | The seed-role table in `config/stage06_seed_manifest.yaml` is the single source of truth (docs generated from it); the v1 pilot role is split into pilot_evaluation (replicates) and pilot_bootstrap (pipeline-execution tests only). Confirmatory seeds never appear as literals in code or notebooks. | Phase D drew a bootstrap from the pilot seed that the v1 note said was never drawn from (erratum E1). | TESTED (V28) |
